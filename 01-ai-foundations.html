Day 1 · What AI actually is

Week 1 · Foundations · ~45–60 min

Learning goals

Distinguish AI, machine learning, deep learning and generative AI; explain training versus inference; distinguish a model from an AI system; and understand why probabilistic systems create distinctive governance problems.

AI is the umbrella

Artificial intelligence is a broad category of systems performing tasks such as prediction, classification, reasoning, perception, language generation or decision support. Machine learning learns patterns from data rather than having every rule explicitly programmed. Deep learning uses multi-layer neural networks. Generative AI creates new text, images, audio, code or other content based on learned patterns.

Governance point: “AI” is too broad to be a useful risk category. Start with the specific system, purpose, users, data, decisions and consequences.

Training vs inference

Training adjusts model parameters using data. Inference is when a trained model receives an input and produces an output. Training raises questions about provenance, rights, bias and documentation; inference raises reliability, misuse, oversight and monitoring questions.

Foundation models

A foundation model can support many downstream tasks. An organization may take a third-party model, add instructions, retrieval, tools and an interface. Therefore model risk is not system risk. The same model used for meeting-title brainstorming and financial eligibility recommendations has radically different consequences.

Probabilistic output

Many AI systems generate predictions or outputs from statistical relationships. Outputs can be plausible and wrong, performance can vary across populations and context, and changes in inputs or surrounding components can alter results. Governance therefore needs context-specific evaluation, monitoring, oversight and reassessment.

Model vs system

The model is one component. The AI system includes the model plus data flows, prompts, retrieval sources, interfaces, business rules, human reviewers, downstream actions, monitoring and organizational processes.

Apply it

A publisher uses an LLM to flag comments that may be defamatory. A moderator reviews every flag before removal. Map: model → comment → instructions → output → moderator → decision → appeal/QA → monitoring. Where can failure occur besides the model?

Knowledge check

1. Same foundation model: copywriting vs financial eligibility. Why does governance risk differ?

2. Best description of an AI system?

Consulting lab

Choose one AI-enabled workflow. Write: purpose → users → provider/model → inputs → outputs → human role → downstream action → people affected → monitoring. That's the skeleton of an AI inventory record.
